Madame, Monsieur,

Nous vous adressons le présent document afin de vous présenter de manière claire et transparente la façon dont nous intégrons l'API de paiement Senfenico au sein de notre application Ritoto Campus. Ce document décrit la nature de notre plateforme, les appels API que nous effectuons, les données échangées, ainsi que les mesures de sécurité mises en œuvre pour garantir la protection des transactions de nos utilisateurs.

1. Présentation de l'application

Ritoto Campus est une plateforme numérique de commande de repas destinée aux étudiants d'un campus universitaire. Elle permet aux étudiants de consulter un menu, composer et passer des commandes en ligne, effectuer un paiement mobile, puis suivre l'état de leur commande en temps réel jusqu'à la livraison dans leur salle de cours.

La plateforme est accessible à l'adresse https://ritoto-campus.com et s'appuie sur une API REST sécurisée hébergée à https://api.ritoto-campus.com. Elle est destinée à un usage interne au campus et s'adresse à quatre catégories d'utilisateurs : les étudiants, les chefs de secteur, les livreurs et les administrateurs.

2. Raison de l'intégration de l'API Senfenico

Le paiement est une étape centrale du parcours étudiant sur Ritoto Campus. La grande majorité de notre public cible ne dispose pas de carte bancaire, mais utilise activement les services de Mobile Money disponibles au Bénin : Orange Money, Moov Money et Sank Money. L'API Senfenico, en agrégeant ces trois opérateurs au sein d'une interface unifiée, nous permet de proposer une expérience de paiement simple, rapide et adaptée aux habitudes de nos utilisateurs.

L'intégration de l'API Senfenico est le seul mécanisme de paiement en ligne de la plateforme. Elle est déclenchée uniquement lors de la confirmation d'une commande par un étudiant. Aucun paiement automatique, aucun abonnement récurrent et aucun prélèvement sans action explicite de l'utilisateur ne sont mis en œuvre.

3. Appels API effectués et justification

Notre intégration repose sur trois points d'entrée de l'API Senfenico. Le tableau ci-dessous détaille chaque appel, son déclencheur et son rôle dans le système.

Endpoint Senfenico Déclencheur Rôle dans Ritoto Campus
POST /v1/payment/charges/ L'étudiant confirme sa commande et clique sur « Payer » Initie la transaction Mobile Money. Transmet le montant (en XOF), le numéro de téléphone de paiement et l'opérateur choisi (Orange Money, Moov Money ou Sank Money). Reçoit en retour une référence de charge (charge_reference), un statut initial et un message d'instruction à afficher à l'étudiant.
POST /v1/payment/charges/submit L'étudiant saisit le code OTP reçu sur son téléphone Soumet le code OTP à Senfenico pour valider la transaction. Reçoit en retour le statut mis à jour de la charge (succès ou échec). En cas de succès, la commande est automatiquement validée dans notre système.
POST /paiements/webhook/
(réception — côté Ritoto)		 Notification asynchrone envoyée par Senfenico Reçoit les mises à jour de statut envoyées par Senfenico (notamment pour les paiements de type pay_offline validés directement par l'opérateur). Le hash de sécurité est vérifié avant tout traitement.

4. Données transmises à l'API Senfenico

Conformément au principe de minimisation des données, nous ne transmettons à Senfenico que les informations strictement nécessaires à l'exécution du paiement.

Donnée transmise Justification
Montant de la commande
(en XOF, entier)		 Montant total calculé côté serveur Django à partir des articles commandés. Le client ne peut pas modifier ce montant : il est toujours calculé et validé par notre backend avant d'être transmis à Senfenico.
Numéro de téléphone
(saisi par l'étudiant)		 Numéro Mobile Money sur lequel la transaction est initiée. Ce numéro est saisi par l'étudiant lors de la composition de sa commande et n'est pas réutilisé en dehors du contexte de paiement.
Opérateur Mobile Money
(orange_bf / moov_bf / sank_bf)		 Sélectionné par l'étudiant parmi les trois opérateurs disponibles. Permet à Senfenico de router la transaction vers le bon réseau.
Code OTP
(reçu par SMS par l'étudiant)		 Code à usage unique envoyé par l'opérateur Mobile Money sur le téléphone de l'étudiant. Transmis à Senfenico pour confirmer l'autorisation de paiement. Il n'est jamais stocké dans notre base de données.

Nous ne transmettons à Senfenico aucune donnée d'identité (nom, prénom, email) ni aucune information bancaire. Les données de paiement ne sont pas partagées avec d'autres services tiers.

5. Description technique du flux de paiement

Le flux de paiement se déroule en cinq étapes successives, entièrement orchestrées côté serveur, à l'exception de la saisie du code OTP par l'étudiant :

  1. L'étudiant finalise sa commande et choisit son opérateur Mobile Money ainsi que le numéro de téléphone à débiter. La commande est enregistrée en base de données avec le statut EN_ATTENTE.
  2. Notre backend appelle POST /v1/payment/charges/ avec le montant, le numéro et l'opérateur. Senfenico retourne une charge_reference unique, un statut initial (send_otp ou pay_offline) et un message d'instruction que nous affichons à l'étudiant.
  3. Si le statut est send_otp, l'étudiant reçoit un code OTP par SMS de son opérateur. Il le saisit dans notre interface. Notre backend transmet ce code à POST /v1/payment/charges/submit avec la charge_reference correspondante.
  4. Senfenico confirme ou rejette le paiement. En cas de succès, notre backend met à jour le statut de la commande en VALIDEE et notifie le chef de secteur concerné en temps réel via WebSocket.
  5. En parallèle (ou dans le cas pay_offline), Senfenico peut envoyer une notification webhook à notre endpoint /paiements/webhook/. Notre serveur vérifie le hash de sécurité avant tout traitement, puis met à jour la commande si elle ne l'est pas déjà.

Aucune donnée de paiement n'est stockée en clair dans notre base de données. Seuls la charge_reference Senfenico et le statut final de la transaction sont conservés, à des fins de traçabilité interne.

6. Sécurité et protection des données

  • Toutes les communications entre notre backend et l'API Senfenico sont chiffrées en TLS 1.2 minimum. La clé API Senfenico est stockée exclusivement en variable d'environnement sur le serveur ; elle n'est jamais exposée au frontend ni versionnée dans le code source.
  • Les webhooks entrants sont systématiquement vérifiés par comparaison du hash SHA-256(payload + SENFENICO_WEBHOOK_SECRET) encodé en Base64, conformément aux recommandations de l'API Senfenico. Toute notification dont le hash est invalide est immédiatement rejetée.
  • Le montant débité est toujours calculé côté serveur à partir des articles de la commande. Le client ne peut pas transmettre un montant arbitraire.
  • Le code OTP est transmis directement de l'interface étudiant vers notre API backend via HTTPS, puis relayé à Senfenico. Il n'est à aucun moment enregistré en base de données.
  • Un mécanisme d'idempotence empêche la création de deux charges Senfenico pour une même commande : avant tout appel à l'API de création de charge, notre backend vérifie qu'aucun paiement n'est déjà associé à la commande.
  • Les logs de transaction (référence de charge, statut, date) sont conservés dans notre base de données PostgreSQL hébergée sur un VPS dédié. La base n'est pas accessible depuis l'extérieur du réseau Docker interne.

7. Audience et volume estimé

Ritoto Campus est une application à usage interne, destinée exclusivement aux étudiants d'un campus universitaire. Elle ne fait pas l'objet d'une ouverture au grand public. Le volume de transactions est directement lié au nombre d'étudiants du campus et au nombre de repas servis quotidiennement.

À titre indicatif, le volume journalier attendu est de l'ordre de quelques dizaines à quelques centaines de transactions, correspondant aux commandes de repas des étudiants inscrits sur la plateforme.
